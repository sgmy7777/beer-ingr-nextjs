# Hop & Barley – интернет‑магазин ингредиентов для домашнего пивоварения

Проект представляет собой учебный e‑commerce‑магазин с каталогом товаров, корзиной, оформлением заказа и собственной системой авторизации. Архитектура разделена на два сервиса:

- **frontend** – Next.js 16 (App Router), SSR, серверные экшены.
- **auth-server** – небольшой Node.js/Express‑сервер с хранением в JSON (LowDB), отвечающий за пользователей, сессии и корзину.

## Возможности

- Каталог ингредиентов (солод, хмель, дрожжи и др.) с фильтрацией и поиском.
- Страница товара с:
  - кнопкой **Add to cart**;
  - переключением на счётчик количества (**+ / −**) после добавления;
  - синхронизацией с реальной корзиной на бекенде.
- Корзина:
  - изменение количества товаров;
  - удаление позиции или всех штук товара;
  - оформление заказа (**Pay**) с визуальным состоянием *Processing…* и очисткой корзины.
- Авторизация:
  - **Sign up / Sign in** через `auth-server`;
  - хранение токена сессии в HTTP‑куках;
  - валидация сессии через `/validate-session`.
- Индикатор количества товаров в корзине в шапке (красный бейдж), который обновляется в реальном времени при:
  - добавлении/удалении товара со страницы продукта;
  - изменении корзины на странице **Cart**;
  - оформлении заказа (после Pay бейдж обнуляется).

## Технологии

- **Frontend**
  - Next.js 16 (App Router, серверные компонентов и server actions)
  - React 19
  - TypeScript
  - CSS‑верстка без UI‑фреймворков
- **Backend (auth-server)**
  - Node.js + Express 5
  - LowDB 7 (файловая JSON‑БД)
  - bcrypt (хэширование паролей)
  - UUID v6/v7 для идентификаторов

## Архитектура

### auth-server

Файлы находятся в директории `auth-server/`.

Основные эндпоинты:

- `POST /signin` – вход по логину/паролю, создаёт сессию и возвращает токен.
- `POST /signup` – регистрация пользователя (при уже существующем логине возвращает редирект 307 на `/signin`).
- `POST /validate-session` – проверка актуальности сессии по токену.
- `POST /signout` – завершение сессии (статус `"ended"`).
- `POST /add-to-cart` – добавление одной единицы товара в корзину текущего пользователя.
- `GET  /cart` – агрегированная корзина пользователя в формате:
  ```json
  [{ "id": "01", "amount": 3 }]
  ```
- `POST /cart/remove-one` – минус одна единица товара.
- `POST /cart/remove-all` – удалить все единицы конкретного товара.
- `POST /cart/clear` – полностью очистить корзину пользователя (используется при оплате).

Данные хранятся в `auth-server/users.json`:

- `users` – список пользователей (id, username, passwordHash).
- `sessions` – активные/завершённые сессии.
- `cart` – «сырые» записи корзины (`productID`, `userID`), которые агрегируются на лету.

### frontend

Файлы находятся в директории `frontend/`.

Ключевые части:

- `app/` – структуры страниц:
  - `/` – каталог товаров с фильтрами/поиском.
  - `/products/[id]` – страница товара c контролом Add to cart.
  - `/cart` – корзина и оформление заказа.
  - `/signin`, `/signup`, `/account` – аутентификация и кабинет пользователя.
- `actions/` – серверные экшены (sign-in, sign-up, is-signed-in, cart checkout, работа с корзиной и т.д.).
- `app/api/cart/update` – API‑роут Next.js для обновления корзины и получения актуального количества товаров (используется на странице товара и для реального времени в бейдже корзины).

## Запуск проекта

### 1. Установка зависимостей

Из корня репозитория:

```bash
cd auth-server
npm install

cd ../frontend
npm install
```

Рекомендуемая версия Node.js: **18+** или **20+**.

### 2. Настройка окружения

#### auth-server

В папке `auth-server/` создайте файл `.env` (можно на основе `.env.example`, если он появится в будущем) со значениями по умолчанию, например:

```bash
PORT=5391
DATABASE_NAME=users
```

Если `.env` отсутствует, сервер:

- слушает порт `5391`;
- использует файл `users.json` в корне `auth-server/` как БД.

Запуск:

```bash
cd auth-server
npm start
```

Сервер поднимется на `http://localhost:5391`.

#### frontend (Next.js)

В папке `frontend/` создайте `.env.local`:

```bash
AUTH_URL=http://localhost:5391
```

Это адрес запущенного `auth-server`, к которому фронтенд ходит за авторизацией и корзиной.

### 3. Запуск фронтенда

```bash
cd frontend
npm run dev
```

По умолчанию Next.js будет доступен на `http://localhost:3000`.

Порядок запуска:

1. Сначала поднимите `auth-server` (`npm start` в `auth-server/`).
2. Затем запустите фронтенд (`npm run dev` в `frontend/`).

## Основные сценарии использования

1. **Регистрация и вход**
   - Перейдите на `/signup`, создайте пользователя.
   - После регистрации вы попадёте на страницу входа `/signin`.
   - После успешного входа токен сессии сохранится в куки, а в шапке появятся иконки аккаунта и корзины.

2. **Добавление товара в корзину**
   - Откройте страницу конкретного товара (`/products/[id]`).
   - Нажмите **Add to Cart**:
     - кнопка превратится в счётчик (**− / количество / +**);
     - красный бейдж на иконке корзины покажет суммарное количество товаров.

3. **Работа с корзиной**
   - На странице `/cart` можно:
     - увеличивать/уменьшать количество товаров;
     - удалять всю позицию;
     - увидеть актуальную итоговую сумму.
   - Все изменения синхронизируются с `auth-server` и отображаются в бейдже корзины.

4. **Оформление заказа**
   - На шаге checkout заполните форму (адрес, способ оплаты).
   - Нажмите **Pay**:
     - кнопка покажет состояние `Processing…` ~3 секунды;
     - корзина очистится через `/cart/clear`;
     - произойдёт переход в личный кабинет `/account`;
     - индикатор корзины в шапке сбросится до нуля.

## Скрипты

### В `auth-server/`

- `npm start` – запуск Express‑сервера с подхватом переменных из `.env` и режимом `--watch`.

### В `frontend/`

- `npm run dev` – запуск Next.js в dev‑режиме.
- `npm run build` – продакшен‑сборка.
- `npm start` – запуск собранного приложения.
- `npm run lint` – запуск ESLint.

## Полезно знать

- Проект учебный, поэтому данные хранятся в JSON‑файле и не претендуют на продакшен‑надёжность.
- Корзина и сессии целиком завязаны на токене в куке и `auth-server`; при его остановке или удалении `users.json` состояние будет потеряно.
- Вся логика UI (кнопка Add to cart, счётчик, бейдж корзины, визуальное состояние Pay → Processing) реализована без сторонних UI‑библиотек — только React/Next и кастомный CSS.

Если вы хотите доработать проект (добавить админку, оплату, историю заказов и т.п.), текущая архитектура легко расширяется: можно заменить LowDB на настоящую БД, повесить auth‑middleware, добавить отдельный API‑слой и т.д.
